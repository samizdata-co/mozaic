# AGENTS.md: working on mozaic

mozaic is a Svelte 5 + d3 chart library with swappable house styles, embeds and print export.
Read `PLAN.md` for the design, `docs/adr/` for decisions and `apps/docs/src/content/` for the guides.

## Layout

- `packages/mozaic/src/lib/`: the library. Each folder is a subpath export (`@samizdata/mozaic/<folder>`).
  - `core/`: `Plot`, `Svg`, `Html`, `Canvas`, `Facets`, `usePlot()`, `useChart()`, `useTheme()`, `useLocale()`, `scaled()`, `position()`, `mm()`.
  - `frame/`: `Chart`, `Header`, `Title`, `Subtitle`, `Footer`, `Source`, `Notes`, `Byline`, `Logo`, `DataTable`, `DataDownload`.
  - `marks/`: `Bars`, `Line`, `Area`, `Points`, `Rects`, `Arcs`, `Text`, `Rules`, `GeoPath`, `Voronoi`, `LineEndLabels`, `Treemap`, `Waffle`, `Dumbbell`, `Arrows`, `Slope`, `Beeswarm` (dots or flags), `Hemicycle`, `Intervals`, `Flag` and `Flags` (circular flags, as in ggflags).
  - `flags/`: square flags from flag-icons (MIT) as inner SVG markup, one named export per upper-case ISO code (`MD`, `RO`, `EU`; Eurostat's `EL`, `UK` as aliases). Generated by `packages/mozaic/scripts/build-flags.js`; don't edit `svgs.ts`. Charts import only the flags they use.
  - `guides/`: `AxisX`, `AxisY`, `GridX`, `GridY`, `Legend`, `ColorRamp`, `SizeLegend`, `Key`.
  - `annotations/`: `Callout`, `Arrow`, `Label`, `RefLine`, `RefBand`.
  - `interactive/`: `PointerArea`, `Tooltip`, `ButtonGroup`, `Scroller`.
  - `table/`: `Table`, `Sparkline`, `toCSV`. `transforms/`: `stack`, `bin`, `groupBy`, `rollup`, `indexTo`, `dodge`, `treemapLayout`, `avoidOverlap`, `hemicycleLayout`, `kernelSmooth`, `loess`, `percentileRank`.
  - `styles/`: the `Theme` type, the neutral `base`, `extendTheme`, `checkTheme`, `rampSteps`, `contrastRatio`. House styles are not here: they live with each brand (`samizdata-co/brand`, `ziaruldegarda/brand`, in `datavis/mozaic/`) or project (plebiscit), and charts take one as `style={theme}`. `locale/`: en, ro, ru. `embed/`: `Embed`, resize protocol, `hostScript`, `embedCode`. `export/`: `figureToSvg`, downloads. `recipes/`: complete chart templates, `BarChart`, `ColumnChart`, `LineChart`, `ScatterChart`, `ArrowChart` (arrow plot: change between two dates per row), `BarDotChart` (bars for the latest value, dots for an earlier one, value and change at the right), `StackedBarChart` (100% stacked bars, brackets over groups of series, reference line), `MosaicChart` (Marimekko: 100% stacked rows as tall as their totals), `PercentileChart` ("how do you compare?": percentile strips per group, a number box and slider for the reader's value, their percentile in each group), `StripChart` (a one-axis beeswarm of dots or flags with labelled highlights and reference lines: many items on one value, much shorter than bars).
  - `src/tests/`: server-render tests with fixtures.
- `packages/mozaic/cli/`: the `mozaic` command (`bin` of `@samizdata/mozaic`): `mozaic export` and `mozaic eject`, plain Node ESM + JSDoc, tests in `cli/test/`. `eject` copies from the shipped `src/lib/recipes/`.
- Projects (one repository per story) are not created here: [maia](https://github.com/samizdata-co/maia), a Copier template, makes them, with the charts in `charts/` (`charts: mozaic`).
- `apps/docs/`: docs site. Copies of the SAMIZDATA and ZdG themes in `src/lib/brands/` (update them from the brand repos; don't edit them) and the Style menu's registry in `src/lib/styles.ts`. Gallery examples in `src/lib/gallery/<slug>/` (`Chart.svelte` + `data.ts`); guides in `src/content/*.md`; the API reference is generated from component sources.

## How a chart is built

```svelte
<Chart {style} {locale} {medium} {width} alt="What the chart shows">
	<Header><Title>…</Title><Subtitle>…</Subtitle></Header>
	<Plot x={scaleLinear().domain([0, 100])} y={scaleBand().domain(names)} height={300}>
		{#snippet children(plot)}
			<Svg>…guides, marks, annotations…</Svg>
			<Html>…tooltips (positions from plot.x / plot.y)…</Html>
		{/snippet}
	</Plot>
	<Footer><Notes>…</Notes><Source>…</Source></Footer>
</Chart>
```

## Rules

- Scales are plain d3 scales. Set the **domain** in chart code; `<Plot>` sets the range.
- Sort, group, stack and compute domains in chart code or `transforms/`, never in marks.
- A new mark is a component that calls `usePlot()` and draws SVG. Use `scaled(scale, value)` (band centres) or `position(plot, x, y)` (also projections). Don't depend on internals.
- Colours come from the theme (`theme.palettes`); text colours from CSS tokens (`var(--mz-color-text)`, `--mz-color-muted`, …). As in Datawrapper, a direct label, an annotation or a key phrase in the title or subtitle may take its series colour, so the text doubles as the legend, if that colour reaches 4.5:1 against the background (`contrastRatio()`); otherwise use a darker shade of it, or a swatch beside text in the text colour. Axes, notes, sources and tooltips use the tokens. Assign categorical colours by entity, in palette order; never cycle past the end. Grey (`semantic.context`) for everything the chart is not about, and one or two strong colours for what it is.
- Anything that must print goes in `<Svg>`. `<Html>`, `<Canvas>`, tooltips and controls are hidden in print.
- Theme-dependent defaults must be `$derived`, not destructuring defaults.
- Use `Accessor<T, Value>`, never `Accessor<T, any>` (it erases callback types).
- A chart form that more than one project could use (not just one dataset) belongs here as a recipe in `recipes/`, not in the project: add it to `recipes/index.ts` (and its `recipes` list) and `src/tests/recipes.spec.ts`; `mozaic eject` finds it by its file name. Projects wrap recipes with their data and strings.
- Every component has an `@component` comment and typed, JSDoc-commented `Props`: the API reference is generated from them.
- Every chart: `alt` text (chart type, data, takeaway), a headline that states one finding true of the data, a subtitle with what is measured, the unit, place and period, a `<Source>`, and all strings per locale.
- Label 2+ series directly (`LineEndLabels`, labels on bars and areas) instead of with a legend. Use `Legend` or `Key` for colour and size scales, for labels that can't fit, and at narrow widths.
- Annotate what the headline depends on (the key value, outliers, events, reference lines) next to the data it explains, with at most two text sizes. At narrow widths, move annotations below the chart or drop the least important; never shrink text.
- Bars, columns and areas start at zero; lines needn't. No rotated tick labels: switch to horizontal bars.
- Numbers: money always has two decimals and whole amounts none (`createLocale(…).money`: 26.14, 12.30, 26); no value shows `.0` or `.00` (`decimals(n)` drops them when a value rounds to a whole number). Recipes take a `format` (and `xFormat`/`yFormat`); pass `money` for prices.
- Every value axis names its unit on its last tick label ("50 lei/m³", "20 c/kWh"): `<AxisY unit>` after the top tick, `<AxisX unit>` after the last labelled one. Tooltips give every value with its unit. Recipes take `unit` (`xUnit`/`yUnit` in `ScatterChart`) for both.
- Say what the space means on strips, beeswarms and scatters: direction arrows at the ends of the axes (`StripChart`/`ScatterChart` `directions`, e.g. "Richer countries →") or quarter labels (`ScatterChart` `quadrants`), which fall back to the arrows when they don't fit. Strips get very soft gridlines.
- Never nest interactive content (a chart can contain links and buttons; don't wrap it in `<a>`).
- Test at 320 px and 1000 px wide, in each style and language, and in print.

## Commands (repo root)

- `pnpm dev`: docs site at http://localhost:5173 (library source hot-reloads via the `mozaic-dev` condition)
- `pnpm check` · `pnpm test` · `pnpm lint` · `pnpm format`
- `pnpm build` then `pnpm test:e2e` (Playwright, axe) and `pnpm export`
- Add a changeset (`.changeset/<name>.md`) with every change to `@samizdata/mozaic` (the only published package; the CLI ships inside it).
- To release to npm, follow the `release` skill (`.claude/skills/release/SKILL.md`): check, `pnpm release` (versions and CHANGELOGs), commit `Release X.Y.Z`, `pnpm release:publish` in the user's terminal (npm 2FA), push `main` and the tag by name, then update and release maia (`../maia`).
